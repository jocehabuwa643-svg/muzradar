# МУЗРАДАР — продукт и онбординг

## Название и слоган

**МУЗРАДАР**

Основной слоган: **«Слушай тех, кто рядом»**

Запасные варианты:
- «Музыка на карте. Люди рядом.»
- «Настройся на город»

## Суть

Гео-социальная сеть и музыкальный радар. Каждый слушатель — точка на живой карте: аватар, текущий трек и индикатор движения (стоит / идёт / едет). Тап по точке — и ты слушаешь то же самое.

## Где решения расходятся с исходным ТЗ и почему

ТЗ выполнено целиком. Ниже места, где буквальное исполнение сломало бы публикацию в сторах, нарушило бы закон или стало бы угрозой для пользователей. Для каждого пункта выбрано ближайшее безопасное решение.

| Пункт ТЗ | Как сделано | Почему |
|---|---|---|
| «Серая» база треков из всех источников | Подключаются только источники, чьи условия разрешают такое использование. Трек помечается как «полный», «превью 30 с» или «недоступен»; недоступные скрыты | Нелицензионный стриминг — прямое основание для отказа в App Store (5.2.1, 5.2.3) и Google Play (IP policy), а в РФ — для вечной блокировки (149-ФЗ ст. 15.6). Архитектура провайдеров позволяет подключить лицензированный каталог (агрегатор или лейбл) без переписывания приложения |
| Опознание по device ID + IP + local storage | Секрет устройства хранится в Keychain/Keystore и дублируется в локальном хранилище. На Android после переустановки аккаунт восстанавливается по хешу Android ID. IP пишется только для антифрода | За одним IP мобильного оператора (CGNAT) сидят тысячи людей: вход по IP отдал бы чужой аккаунт. Apple прямо запрещает опознавать устройство по сетевому подключению |
| Каждый виден на карте в реальном времени | Виден каждый, но с размытием: для незнакомцев — ячейка около 1 км со стабильным смещением, для взаимных подписок (по желанию) — около 150 м. Истории перемещений нет. Точность задаётся настройкой сервера | Точные координаты вместе с фото лица и движением в реальном времени — инструмент для преследования. Snap Map и Zenly пришли к тому же |
| Запрос геолокации первым шагом | Сохранено: геолокация — шаг 1. Сразу за ним добавлен шаг «Согласия и возраст». До этого шага на сервер ничего не отправляется | 152-ФЗ (с 01.09.2025) требует отдельного согласия на обработку данных и ещё одного — на их показ другим (ст. 10.1). Сторы требуют правила, возрастные ограничения и защиту подростков |
| Приложение полностью блокируется без геолокации | Сделано как в ТЗ. Жёсткость блокировки вынесена в один флаг: `hard` блокирует всё, `map-only` — только карту | Apple 5.1.1(iv) требует альтернативу, если данные не нужны для основной функции, а музыке геолокация не нужна. Если ревью отклонит сборку, флаг переключается за минуту |
| Абсолютно стабильный фон | Один долгоживущий плеер вне React, очередь в JS, фоновый режим через expo-audio. Следующий/предыдущий на экране блокировки — после перехода на Expo SDK 58 | `react-native-track-player` 4 не работает на новой архитектуре RN, v5 платная. В expo-audio 57 нет next/prev на локскрине, в 58 они есть |
| Трансляция позиции, пока едешь | MVP: позиция обновляется, пока приложение открыто. В фоне уходит только текущий трек: пока играет музыка, точка остаётся в последней ячейке (до 8 часов), без музыки исчезает через 2 минуты. Режим «Live» (непрерывная позиция в фоне) реализован за флагом `LIVE_LOCATION` | Google Play относит непрерывную фоновую геолокацию к особой политике с декларацией и видео; «слушать музыку» не считается для неё основанием. Режим «Live» с явным включением пользователем — фаза 2 |
| AI-поиск | Слой LLM не привязан к провайдеру. Claude используется для поддерживаемых регионов, для РФ подключается российский провайдер. В промпт уходит только текст запроса | Россия не входит в список поддерживаемых регионов Claude API, а передача данных за рубеж — отдельная процедура по 152-ФЗ |

## Онбординг: пошаговый флоу

Состояние онбординга сохраняется локально после каждого шага. Если приложение закрыть посреди онбординга, оно продолжит с того же места.

### 0. Запуск (splash)

1. Читаем секрет устройства из SecureStore и локальное состояние онбординга.
2. Онбординг завершён → обмениваем секрет на токен (`POST /v1/auth/device`) → сразу **карта**. Нет сети → карта из кэша профиля, переподключение в фоне.
3. Сервер не знает секрет (аккаунт удалён) → сбрасываем локальное состояние и возвращаемся на шаг 1.
4. Онбординг не завершён → продолжаем с последнего пройденного шага.

Глобальный гейт геолокации работает и после онбординга: если пользователь отозвал разрешение или выключил геолокацию, приложение блокируется (режим `hard`) до восстановления. Проверка — при каждом возврате в приложение.

### 1. Геолокация (блокирующий шаг)

- Экран-объяснение: зачем нужна геолокация и что увидят другие (приблизительная зона, а не точка).
- Кнопка «Разрешить» → системный запрос «При использовании приложения». Фоновое разрешение не запрашивается.
- Состояния и реакции:
  - `services_off` — «Геолокация на телефоне выключена» → «Включить» (Android: системный диалог, иначе экран настроек; iOS: инструкция и переход в Настройки);
  - `undetermined` / `denied_can_ask` — «Разрешить»;
  - `blocked` (отказ навсегда) — «Открыть настройки»;
  - `ok_approx` (приблизительная геолокация) — пропускаем и мягко предлагаем точную;
  - `ok` — дальше.
- Пока доступа нет, дальше пройти нельзя. Предупреждение: **«Без геолокации МУЗРАДАР не работает»**.

### 2. Согласия и возраст

- Год рождения. Младше 16 — отказ в регистрации. 16–17 — видимость только для взаимных подписок, режим-невидимка включён по умолчанию.
- Отдельный чекбокс: согласие на обработку персональных данных (ссылка на документ).
- Отдельный чекбокс: согласие на распространение — другие видят имя, фото, текущий трек и приблизительное местоположение.
- Принятие правил сообщества (запрет травли, CSAE, жалобы и блокировки).
- По кнопке «Продолжить»: `POST /v1/auth/device` (создаётся аккаунт) → `PUT /v1/me/consents` (год рождения, версии документов, время согласия). Это первые данные, которые уходят на сервер.

### 3. Имя

- От 2 до 24 символов: буквы, цифры, пробел, `-`, `_`, `.`. Без ссылок.
- Фильтр запрещённых слов на клиенте (подсказка) и на сервере (решение).

### 4. Аватар — только камера

- Запрос доступа к камере с понятным текстом. При отказе навсегда — «Открыть настройки».
- Фронтальная камера на весь экран, круглая рамка-маска, подсказка «Лицо в круг, смотрите прямо».
- Галереи нет: ни кнопки, ни зависимости, ни разрешения на медиатеку. Сборка это проверяет.
- Снимок → нормализация до 720 px → детекция лица на устройстве (ML Kit) → проверка:
  - ровно одно лицо;
  - лицо в центре и крупно (25–80 % ширины кадра);
  - анфас (поворот головы ≤ 20°, наклон ≤ 15°).
- Кроп квадрата по лицу с запасом → 128×128 WebP с качеством 0,6 (около 1,5 КБ).
- Предпросмотр в круге: «Переснять» / «Готово». При неудачной проверке — конкретная причина: «лица не видно», «в кадре несколько лиц», «подойдите ближе», «смотрите прямо».
- «Готово» → `PUT /v1/me/avatar`. Сервер перекодирует снимок (128×128 WebP, метаданные стираются) и делает для карты круглую версию с прозрачными углами. Лицо не используется для идентификации, поэтому по позиции Роскомнадзора это не биометрия.

### 5. Музыкальный вкус

- Жанры: минимум 3 (сетка чипов).
- Настроения: минимум 1 (спорт, в машине, ночь, работа, фокус, чилл, вечеринка, романтика, грусть).
- Артисты: минимум 1, из подсказок под выбранные жанры или через поиск.

### 6. Завершение

1. `PUT /v1/me/profile` — имя и вкус. Сервер проверяет, что пройдены все шаги (согласия, аватар, имя, вкус), отмечает онбординг и выдаёт новый токен с доступом к карте и музыке.
2. Анимация «Вы в эфире» (развёртка радара) → **карта**.

При ошибке сети введённые данные остаются, кнопка «Повторить» продолжает с упавшего запроса. Если приложение переустановлено посреди онбординга, сервер возвращает уже пройденные шаги и продолжение начинается с первого незавершённого.

### Повторный запуск

- Splash → секрет из Keychain/Keystore → токен → карта. Онбординг не показывается.
- Переустановка на iOS: запись в Keychain переживает удаление приложения, аккаунт тот же.
- Переустановка на Android: Keystore очищается, аккаунт восстанавливается по хешу Android ID (он привязан к ключу подписи приложения).
- Новый телефон: восстановление через SMS или Госуслуги (фаза 2).
