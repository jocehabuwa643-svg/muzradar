# МУЗРАДАР — тест PWA и preview APK

## PWA на телефоне
1. `npm run export:web -w @muzradar/mobile`.
2. `npm run tunnel:up -- localhost` (нужен SSH; ngrok/Cloudflare тоже поддерживаются).
3. Откройте выданный HTTPS-адрес в браузере телефона. Меню браузера → **«Установить» / «На экран Домой»**.
4. Пройдите геолокацию → согласия → имя → фото с камеры → вкус. Галерея не используется, лицо проверяется локально MediaPipe.
5. Проверьте карту, каталог и «Слушать вместе». PWA геолокация работает только foreground; фоновый звук зависит от браузера.

## Android preview APK

## Как это устроено
- **Сервер:** `npm run dev:server` из корня репо → Fastify на `0.0.0.0:8080`. База — встроенный PGlite (`apps/server/.data/`, без Docker), присутствие хранится в памяти процесса.
- **Адрес для телефона:** `http://<IP ПК в Wi-Fi>:8080` (на момент записи — `192.168.0.107`, проверить: `ipconfig`). API — `/v1/...`; сокеты — тот же адрес, путь `/v1/realtime` (только websocket).
- **Адрес зашит в APK при сборке:** `apps/mobile/eas.json` → профиль `preview` → `EXPO_PUBLIC_API_URL`. Если сменился IP ПК — впиши новый адрес и пересобери.
- **HTTP без шифрования** разрешён только в тестовых сборках. В production он выключен, сервер работает только за HTTPS.
- **CORS менять не нужно:** это нативное приложение, а не браузер.

## Один раз
1. **Брандмауэр.** PowerShell от администратора: Wi-Fi сейчас помечена как общественная сеть, и входящие соединения закрыты.
   ```
   Set-NetConnectionProfile -InterfaceAlias "Беспроводная сеть" -NetworkCategory Private
   New-NetFirewallRule -DisplayName "MUZRADAR dev 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow -Profile Private
   ```
2. **Сборка APK** (PowerShell, из `apps\mobile`):
   ```
   npx eas-cli login
   $env:EAS_NO_VCS=1; $env:EAS_PROJECT_ROOT=(Resolve-Path ..\..).Path; npx eas-cli build -p android --profile preview
   ```
   - На вопрос о создании проекта ответь «да».
   - Если EAS попросит вписать `projectId`, добавь его в `apps/mobile/app.json` так: `{"expo":{"extra":{"eas":{"projectId":"…"}}}}`.
   - В конце EAS даст ссылку и QR-код на APK, они же будут на expo.dev.
   - `EAS_NO_VCS` нужен, потому что в репозитории нет коммитов.

## Каждый тест
- **Поднять сервер:** `npm run dev:server` в корне репо. Окно не закрывай.
- **Проверить с телефона:** открой в браузере `http://192.168.0.107:8080/health` → должно прийти `{"ok":true,...}`.
- **Остановить:** Ctrl+C в окне сервера. Если процесс завис:
  `Get-NetTCPConnection -LocalPort 8080 -State Listen | % { Stop-Process -Id $_.OwningProcess -Force }`
- **Телефон не в той же Wi-Fi:** только через `npm run tunnel:up` / `npm run tunnel:down` — см. [DEPLOY.md](DEPLOY.md). Скрипт не выпустит сервер наружу без своих секретов в `apps/server/.env` и сам впишет https-адрес в `eas.json`. Ручной `cloudflared` в обход скрипта не запускать.

## Чеклист на 10 минут (два Android-телефона A и B с этим APK)
- [ ] Сервер поднят, `/health` открывается в браузере обоих телефонов.
- [ ] APK установлен (разрешить установку из этого источника). Адрес вписывать не нужно — он зашит.
- [ ] Онбординг на обоих: геолокация → согласия → имя → фото с камеры → вкус.
- **Точная геолокация (A):**
  - [ ] A включает трек. B на радаре видит пин A с названием трека. Живые точки видны с зума 12 — сильно не отдаляй.
  - [ ] B тапает по A → «Слушать вместе» → играет тот же трек с того же места.
  - [ ] B сворачивает приложение и блокирует экран → музыка играет, в уведомлении название трека.
- **Приблизительная геолокация (A):**
  - [ ] На A: Настройки → Приложения → МУЗРАДАР (preview) → Разрешения → Местоположение → «Точное местоположение» выкл. Вернуться в приложение.
  - [ ] У B вместо пина — зона-квартал: полупрозрачный прямоугольник ≈1,4 км, пунктирная рамка, приглушённый аватар, название трека. Тап по зоне → «где-то в этом районе» → «Слушать вместе» → тот же трек.
  - [ ] A снова включает точную геолокацию и возвращается в приложение: за несколько секунд зона у B схлопывается в пин.
- **Если что-то не так:** смотри логи в окне сервера, запросы там видны построчно. Если `/health` не открывается с телефона — дело в брандмауэре или в разных Wi-Fi.

## Потом: российский VPS (Timeweb Cloud / Selectel)
Архитектура та же, меняются только переменные окружения.
- **Сервер:** Node 22+ на VM или в контейнере; запуск — `npm ci && npm run build -w @muzradar/shared && npm run build -w @muzradar/server && node apps/server/dist/index.js` под systemd или pm2.
- **База:** управляемый PostgreSQL 18 → `DATABASE_URL`; PGlite там не используется.
- **Redis:** управляемый или на той же VM → `REDIS_URL`. Перед этим один раз прогони Redis-тесты присутствия.
- **Секреты:** `JWT_SECRET`, `PRESENCE_JITTER_SECRET`, `ANDROID_ID_PEPPER`.
- **Снаружи:** Caddy или nginx с TLS на домене (например, `api.muzradar.ru`), проксирование websocket-апгрейда на `/v1/realtime`; `TRUST_PROXY` задаётся CIDR прокси.
- **Мобилка:** профиль `production` с `EXPO_PUBLIC_API_URL=https://api…`; HTTP без шифрования там остаётся выключенным.
- **152-ФЗ:** хостинг в РФ закрывает локализацию данных.
- **Проверить заранее:** доступность Audius, archive.org и Commons с российского IP. Отсюда это не проверялось: здесь исходящий трафик идёт не из РФ.
