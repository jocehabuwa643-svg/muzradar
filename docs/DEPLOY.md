# МУЗРАДАР — GitHub, тест с друзьями, перенос на VPS

МУЗРАДАР — это Android-приложение (Expo) плюс Node-сервер с сокетами `/v1/realtime`. Сервер должен работать как постоянный процесс. **Netlify и GitHub Pages отдают только статические файлы: сервер и сокеты там не живут и не будут.**

## 2. Живой тест: сервер на ПК + https-туннель (главный путь)
```powershell
npm run tunnel:up     # сервер :8080 + туннель, проверка /health по https, адрес → eas.json (preview)
npm run tunnel:down   # остановить сервер и туннель, освободить порты 8080/54329
```
- **Секреты** лежат в `apps/server/.env` (создан, в .gitignore). Без них `tunnel:up` откажется выпускать сервер наружу.
- **Адрес Cloudflare quick tunnel** новый при каждом `up`. Поэтому порядок такой: `up` → сборка APK → тест. Туннель перезапустил — APK пересобрать.
- **Логи** в `apps/server/.data/tunnel/`. Там IP друзей, после теста удали.

**Статус на 2026-09-23: Cloudflare с этого ПК не работает.**
1. VPN happ не пропускает исходящий порт 7844 (ни QUIC, ни TCP), и cloudflared не может подключиться к Cloudflare. Проверено трижды: скрипт за ~50 с падает с этой причиной и сам всё убирает.
2. Даже если туннель поднимется, с 9 июня 2025 года российские провайдеры режут трафик к Cloudflare до первых 16 КБ ([блог Cloudflare](https://blog.cloudflare.com/russian-internet-users-are-unable-to-access-the-open-internet/)). У друзей в РФ без VPN каталог и сокеты не загрузятся.

Итог: Cloudflare подходит только для друзей за рубежом или с VPN, и только если VPN на ПК пропускает порт 7844 (или cloudflared исключён из VPN).

**Запасной путь — ngrok (работает через порт 443):**
1. Зарегистрируйся на ngrok.com, сам.
2. Выполни: `winget install --id Ngrok.Ngrok -e`, затем `ngrok update`, затем `ngrok config add-authtoken <токен>`. Токен вводишь сам, никуда больше его не вставляй.
3. В кабинете ngrok, раздел Domains, найди свой бесплатный dev-домен: он выдаётся аккаунту автоматически, вида `https://<имя>.ngrok-free.app` или `.ngrok-free.dev`.
4. Запусти: `npm run tunnel:up -- ngrok https://<твой домен>`. **Адрес постоянный, APK собирается один раз.**
5. Проверь у друга: открой `<адрес>/health` в браузере его телефона. Браузеру бесплатный ngrok сначала показывает страницу-предупреждение, нажми Visit Site. Приложение и сокеты её не видят ([лимиты free-плана](https://ngrok.com/docs/pricing-limits/free-plan-limits)). Работает ли ngrok из российских сетей, заранее не проверено.
6. Лимиты бесплатного ngrok: 1 ГБ исходящего трафика и 20 000 HTTP-запросов в месяц. Для теста с друзьями этого хватает: музыка идёт в телефон напрямую от источников, а не через сервер.

**Твой телефон в той же Wi-Fi** — туннель не нужен, см. [DEVICE-TEST.md](DEVICE-TEST.md).

## 3. APK (EAS) — входишь сам
```powershell
cd "C:\Users\Huawei\Desktop\МУЗ РАДАР\apps\mobile"
npx eas-cli login
$env:EAS_NO_VCS=1; $env:EAS_PROJECT_ROOT=(Resolve-Path ..\..).Path; npx eas-cli build -p android --profile preview
```
- **Перед сборкой** сначала `tunnel:up`, потом убедись, что в `apps/mobile/eas.json` в `preview.env.EXPO_PUBLIC_API_URL` стоит **https-адрес туннеля**. Скрипт обновляет его автоматически.
- **`EAS_NO_VCS=1`** позволяет собрать текущее рабочее дерево без коммита.
- **В конце** EAS выдаст ссылку и QR-код на APK.

## 4. PWA — тот же backend, без статического «пустого» хостинга
PWA собирается из того же Expo-приложения: `react-native-web`, MapLibre GL, браузерные геолокация/камера и локальная MediaPipe Face Landmarker. Netlify/GitHub Pages не нужны: Fastify сам отдаёт собранную PWA, `/v1/...` и websocket на одном HTTPS-origin.

```bash
npm run export:web -w @muzradar/mobile
npm run tunnel:up -- localhost
```

`localhost` использует localhost.run через SSH без аккаунта; адрес меняется при каждом запуске. Альтернативы: `cloudflare` (на этом ПК сеть его не пропускает) и `ngrok` (нужен свой токен; постоянный домен удобнее для APK). `PWA_STATIC_DIR` включается скриптом автоматически, если `apps/mobile/dist/index.html` существует. Остановка: `npm run tunnel:down`.

Ограничения PWA: геолокация только foreground, фоновое звучание зависит от браузера, секрет установки живёт в localStorage и теряется при очистке данных сайта. Camera-only и проверка лица сохранены; галерея не запрашивается. Для полного native-фона используйте APK.

## 5. Что можно проверить сегодня
- **PWA в браузере телефона:** открыть HTTPS-ссылку туннеля → «Установить / На экран Домой» → онбординг → радар → каталог → «Слушать вместе». Нужны геолокация и камера.
- **Android по Wi-Fi:** полный сценарий с preview APK (сначала открыть порт 8080 в брандмауэре, см. DEVICE-TEST.md).
- **Android через туннель:** после сборки preview APK работают онбординг, каталог, радар, совместное прослушивание и музыка в фоне.
- **Ограничения:** iPhone-сборки нет; работа 24/7 зависит от включённого ПК; Cloudflare на этом ПК недоступен; фон в PWA зависит от браузера.
- **Ссылку и APK — только близким друзьям, публично не выкладывать.** Регистрация открыта всем. Запрос `/v1/presence/nearby` не ограничивает размер области и может вернуть сразу много людей по всему миру. У каталога нет лимита запросов. До публичного теста это закрывается правкой кода.

## 6. Перенос на Timeweb (потом, не сейчас)
- **Нужен VPS, а не виртуальный хостинг.** Виртуальный хостинг не держит постоянно работающий Node-процесс с сокетами.
- **Старт:** 2 ГБ RAM, Ubuntu LTS.
  - **Cloud MSK 40**, Москва: 2 vCPU, 2 ГБ, 40 ГБ NVMe. На 2026-09-23 это самый дешёвый московский тариф с 2 ГБ, 800 ₽/мес **без IPv4**.
  - **Публичный IPv4** оплачивается отдельно, а серверу для приложения он нужен.
  - **Cloud MSK 30** (1 vCPU, 2 ГБ, 30 ГБ) есть только в прайсе от ноября 2025 года, в каталоге сайта его сейчас нет.
  - **Цены** уточняй на [timeweb.cloud/prices](https://timeweb.cloud/prices).
- **Стек:** Node 22+, Caddy (HTTPS сам через Let's Encrypt) или nginx, systemd.
- **Postgres нужен сразу.** В `NODE_ENV=production` сервер без `DATABASE_URL` не стартует, а встроенная PGlite — только для dev. Postgres на том же VPS или управляемый.
- **Redis** можно позже: пока нода одна, присутствие держится в памяти процесса.
- **Что копируется:** только код — `git clone`, `npm ci`, затем `npm run build -w @muzradar/shared && npm run build -w @muzradar/server`, запуск `node dist/index.js` из `apps/server` под systemd. Миграции применяются сами при старте. Сборка и `node dist/index.js` проверены локально на встроенной базе; с настоящим Postgres в `production` — ещё нет.
- **Что не копируется:** `.env` с ПК (на сервере новые секреты) и `.data/` (dev-база с тестовыми людьми).
- **Меняются env:**
  - `NODE_ENV=production`;
  - `DATABASE_URL`;
  - `JWT_SECRET`, `PRESENCE_JITTER_SECRET`, `ANDROID_ID_PEPPER` — новые, каждый ≥ 32 символа;
  - `TRUST_PROXY=127.0.0.1,::1` (прокси на том же хосте);
  - позже `REDIS_URL`;
  - при веб-оболочке — `CORS_ORIGINS`.
- **Снаружи:** домен `api.<домен>` с A-записью на IP VPS, прокси с TLS и пропуском websocket на `/v1/realtime`. **Cloudflare перед сервером не ставить** — в РФ он режется.
- **В APK заново прописывается** только `EXPO_PUBLIC_API_URL=https://api.<домен>`, в профиле `production` (или `preview`). Одна пересборка — дальше адрес не меняется.

**Перенос лёгкий: архитектура та же, меняются только URL и env.** Код сервера и приложения не трогается. Туннель заменяется настоящим доменом на российском IP. Встроенная база заменяется Postgres через `DATABASE_URL`. Секреты создаются заново на сервере. APK пересобирается один раз под постоянный https-адрес, и после этого друзьям не нужны ни твой включённый ПК, ни VPN.
